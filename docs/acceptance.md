# اختبار القبول قبل التسليم

لا يُعتبر النظام مُسلَّماً بمجرد انتهاء البرمجة. الترتيب المتفق عليه:

1. تشغيل المسار كاملاً على بيانات واقعية: مورد، مادة، أمر شراء، اعتماد، استلام، تحويل، وصفة، أمر إنتاج، إكمال مع هدر، فاتورة ضريبية، تحصيل، قيد، تقرير تتبع.
2. تجربة الحسابات الثلاثة والتأكد أن المحاسب لا يعدّل المخزون وأن العمليات لا تعتمد أمر الشراء.
3. طباعة فاتورة وأمر شراء وملصق باركود، وتصدير Excel للقيود.
4. استخدام النظام في العمل الفعلي لمدة **أسبوع**.
5. إصلاح الأعطال الحرجة التي تظهر خلال الأسبوع قبل القبول النهائي.

اختبارات المحرك الآلية تغطي قواعد الرصيد والاعتماد والضريبة 5% وميزان القيود:

```bash
pnpm test:erp
```

بيانات المصنع التجريبية جاهزة داخل النظام (ذرة، صويا تحت الحد، أمر شراء معلّق، فاتورة جزئية، مصروف وراتب بانتظار الاعتماد) حتى يبدأ الأسبوع التشغيلي من وضع قريب من الواقع.
